# 모에니 0.0.6 시험 절차

이 버전은 전체 Blob HLS 목록과 실제 영상 조각 요청의 `gets` 헤더를 로컬 프록시로 넘기는 시험판이다. **같은 기기에서 Node 프록시를 실행해야 하며**, Android 망가요미 실기기 재생까지 검증한 정식판은 아니다.

## 업데이트와 실행

망가요미의 애니 시험 저장소 인덱스를 새로고침하고 `[시험] 모에니`를 `0.0.6`으로 업데이트한다. 저장소 주소는 아래와 같으며 정식 저장소와는 별개다.

```text
https://raw.githubusercontent.com/insid0909-max/aniyomi-extensions/test/index.json
```

프록시 소스 파일을 망가요미가 설치된 같은 휴대폰으로 가져온다. 아래 파일은 직접 검토할 수 있는 Node 스크립트이며 별도의 npm 패키지가 필요하지 않다.

[모에니 로컬 프록시 소스](https://raw.githubusercontent.com/insid0909-max/aniyomi-extensions/test/tools/moeni-loopback-bridge.cjs)

Termux 등에서 Node 20 이상을 준비하고 프록시를 실행한다. PC에서 실행한 `127.0.0.1`은 휴대폰의 `127.0.0.1`이 아니므로 같은 기기에서 실행해야 한다.

```sh
pkg install nodejs
node --version
# 프록시 파일을 저장한 폴더에서 실행
node moeni-loopback-bridge.cjs
```

프록시는 `127.0.0.1:17889`에만 바인딩하고 시작 화면에 64자리 로컬 등록 키를 표시한다. 망가요미의 `[시험] 모에니` 소스 설정에서 `로컬 HLS 프록시 등록 키` 항목에 그 값을 입력하고, 프록시 프로세스를 유지한 채 회차를 재생한다.

등록 키는 사이트의 로그인 토큰이나 `gets` 값이 아니며, 사이트 토큰을 직접 입력할 필요도 없다. 키는 `.config/moeni-loopback-bridge/config.json`에 저장되므로 채팅·스크린샷·로그로 공유하지 않는다.

## 확인할 항목

- **업데이트:** 설치된 이름이 `[시험] 모에니`, 버전이 `0.0.6`인지 확인한다.
- **설정:** `로컬 HLS 프록시 등록 키` 항목이 나타나고 정상적으로 저장되는지 확인한다.
- **초기 재생:** 동일 회차에서 2초 이후에도 이어지는지 확인한다. 필터의 마지막 재생 진단에 전체 조각 개수와 길이가 표시되는지도 확인한다.
- **연속 재생:** 60초 이상 재생, 중간 탐색, 일시정지·복귀를 나눠 확인한다. 전체 본편 완주 여부는 별도로 기록한다.
- **오류:** 오류 코드·문구·발생 시간과 “처음부터 안 됨/몇 초 뒤 중단/다음 회차 이동”을 기록한다. 토큰·서명 URL·로컬 등록 키는 제외한다.

## 진단 코드

- **`BRIDGE_SETUP`:** 확장 설정의 로컬 등록 키가 비어 있거나 형식이 맞지 않는다. 프록시 화면의 64자리 키를 확인한다.
- **`BRIDGE_OFFLINE`:** 같은 기기의 프록시에 연결하지 못했다. Termux 실행 상태와 `127.0.0.1:17889` 사용 여부를 확인한다.
- **`BRIDGE_HTTP`:** 등록 키 불일치, 목록 거부 또는 세션 수 제한 등으로 프록시가 등록을 거부했다. HTTP 상태 번호와 함께 기록한다.
- **`noep`:** WebView에서 요청 회차 링크를 찾지 못했다. 작품·회차와 앱에 표시된 오류를 기록한다.
- **`no_manifest`:** 정상 페이지의 전체 목록을 관찰하지 못했다. 페이지 로딩 또는 WebView 검사 문제일 수 있으며 원인을 확정한 것은 아니다.
- **`manifest_without_matching_gets`:** 목록은 있지만 그 목록의 조각과 대응하는 `gets` 요청을 관찰하지 못했다. 임의 토큰으로 대체하지 않는다.
- **`rotating_gets_requires_live_webview`:** 관찰한 대응 요청들에서 서로 다른 `gets` 값이 나왔다. 고정 헤더 인계를 성공으로 처리하지 않는다.

## 구현과 검증 범위

기존 확장에는 `/vod/` 주소를 HLS 후보로 판단하고 단일 TS도 회차로 반환할 수 있는 경로가 있었다. 이번 버전은 이를 차단하고 정상 페이지가 이미 생성한 전체 목록을 관찰하여 인계한다. ([수정 전 확장](https://raw.githubusercontent.com/insid0909-max/aniyomi-extensions/4377b79ea0df82c50c7a76bf777708b5793ab30f/js/moeni.js))

확인한 사이트 플레이어는 Blob 재생목록과 `gets` 요청 헤더를 사용하며, `ini`가 있는 경우 초기화 Blob도 생성한다. 이 버전은 해당 데이터를 관찰하지만 API 응답을 성공으로 위조하거나 사이트의 `admin` 값을 설정하지 않는다. ([분석한 플레이어 번들](https://moeni.net/assets/index-4C2VvNfc.js))

실제 목록 402개 조각, 약 1,420.043초를 확보했으며, 원본 페이지를 닫은 상태에서 로컬 프록시를 통해 FFmpeg로 75초를 실시간 디코딩했다. 이 결과는 해당 회차·세션의 개발 환경 시험이며 모든 회차의 Android 재생이나 전체 완주를 보장하지 않는다.

자동 검사는 다음 명령으로 실행할 수 있다. Client·WebView 모의 시험과 실제 루프백 HTTP 검사를 포함하며, 휴대폰 플레이어 시험을 대체하지 않는다.

```sh
node --check js/moeni.js
node --check tools/moeni-loopback-bridge.cjs
node --test tests/moeni-*.test.cjs
git diff --check
```

## 한계와 보안

- **실기기:** 사용자 앱 버전, WebView의 페이지 이탈, Termux 프로세스 유지와 네이티브 디코딩은 추가 확인이 필요하다.
- **장시간:** 본편 완주·토큰 만료·장시간 일시정지 이후 재개는 미검증이다. 서버가 401/403을 반환하면 새 토큰을 만들어내지 않고 오류를 전달한다.
- **자막:** 사이트의 ASS worker 자막을 앱 자막으로 인계하는 기능은 포함하지 않는다.
- **범위:** 완료된 단일 media VOD만 지원한다. 라이브·별도 오디오 rendition master·상대 미디어 URI·원격 리다이렉트·허용 도메인 밖 CDN은 거부한다.
- **네트워크:** 브라우저와 Node의 외부 IP가 달라지는 앱별 VPN 구성은 별도 문제를 일으킬 수 있다. 쿠키 저장소 동기화나 가짜 heartbeat 전송은 하지 않는다.
- **로컬 서버:** 등록 키와 임의 재생 세션 URL은 공유하지 않는다. 원격 요청은 HTTPS의 `modumo.bid` 및 하위 도메인 `/vod/`로 제한하고 사설 DNS 주소·리다이렉트·브라우저 Origin 요청을 차단한다.
- **정식판:** 이 변경은 `test` 브랜치의 시험 소스와 인덱스에만 적용한다. `master` 정식 소스와 정식 인덱스는 변경하지 않는다.
